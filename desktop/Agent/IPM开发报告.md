# IPM 与 KnowClaw 阶段性升级报告

## 一、升级背景

本轮 IPM 与 KnowClaw 升级围绕三个目标展开：第一，修复 v1 版本中用户已经明确反馈的体验问题；第二，将 KnowClaw 从基础对话助手升级为能够理解工作空间、调用工具、生成文件、整理资料、处理网页和多模态材料的 Agent；第三，补齐悬浮窗场景，让 AI 能够在不打断主工作流的情况下随时被调用。

从开发记录看，本轮升级覆盖了多个相互衔接的工作包：`KNOWCLAW_REBUILD_PLAN` 完成了底层重建，`KNOWCLAW_UPGRADE_PLAN` 完成了 U0-U8 的 Agent 能力升级，`IPM_FEATURE_UPGRADE_PLAN` 完成了文件接入、网页抓取、OCR、工作空间文件树和悬浮窗 KnowClaw，`SKILL_SYSTEM_PLAN` 完成了 Skill 管理与导入体系，`FLOATING_KNOWCLAW_PLAN` 完成了悬浮助手八个阶段，`IPM_CORE_UPGRADE_PLAN` 完成了核心体验中的关键反馈优化。

这意味着本轮迭代不是单个功能点的更新，而是一次从“应用可用性”到“AI 工作流能力”的系统性升级。

## 二、整体建设成果

### 1. KnowClaw 底层重建完成

KnowClaw 早期版本已经具备对话和部分工具调用能力，但整体架构仍偏向“功能拼接”。本轮首先完成了底层重建，使 KnowClaw 拥有更稳定的会话、工具、模型、Skill 和历史记录基础。

主要完成内容包括：

- **P0 基础 PoC 通道打通**：完成最小运行链路，验证新的 Agent Runtime 可以被 IPM 桌面应用调用。
- **P1 凭证与模型桥接**：接入模型清单、模型切换和 OpenAI provider，为后续多模型能力打基础。
- **P2 会话存储与 SessionManager**：支持 JSONL 会话持久化，保证对话可以恢复、继续和追溯。
- **P3 主进程到渲染进程事件桥**：完成 IPC 事件通道，使工具调用、模型回复、状态变化能够实时传到前端。
- **P4 KnowClaw V2 独立面板**：建立新的聊天界面，支持模型切换、中止、新对话等基础交互。
- **P5 IPM 业务工具接入**：把项目、案件、文件等业务能力以工具形式注入 Agent。
- **P6 网络工具整理**：保留和迁移网页抓取能力，为后续搜索和剪藏升级提供基础。
- **P7 系统提示词与资源加载器**：将提示词、工具描述、用户上下文等统一管理，减少硬编码。
- **P8 Skill 路径接入**：建立内置 Skill 目录和 skill-builder 能力。
- **P10 历史会话 UI**：支持会话列表、打开历史会话和继续工作。
- **P12 旧实现清理**：删除旧 supervisor / project-agent 实现，减少系统负担。
- **P13 架构文档收尾**：补齐 pi-runtime 与 Agent 子系统说明，方便后续维护。

其中 P9 和 P11 根据实施判断跳过：P9 的“旧项目专员委托”被后续更完整的子任务能力替代；P11 的“双轨切换”因新旧入口已分离，直接进入旧实现清理更合理。

这部分工作对非技术用户不一定直接可见，但它决定了后续功能是否稳定、是否可扩展、是否能持续迭代。

## 三、v1 用户反馈优化

### 1. 项目与案件文件夹支持更高自由度的自定义

v1 版本中，项目/案件目录结构较固定，用户在真实业务中经常会遇到“现有资料结构和系统默认结构不一致”的情况。本轮完成了业务文件夹自定义能力，重点是把目录管理权还给用户，同时保留系统必要的安全边界。

已经完成的工作包括：

- 业务文件夹支持删除、重命名、移动等管理操作；
- 新建项目/案件时支持“默认四类模板”和“空白结构”两种选择；
- 系统目录仍受保护，避免误删 `meta`、`temp` 等关键目录；
- 删除文件夹前会识别是否存在未处理的 AI suggestion，避免误删仍有关联建议的目录；
- 文件管理 Header 做了路径化处理，减少页面上重复展示项目名、案件名造成的视觉噪音。

这项优化的核心价值是让 IPM 更贴近真实业务资料形态，而不是要求用户迁就系统预设结构。

**演示内容**

在项目或案件工作空间中展示业务文件夹的自定义能力：

1. 进入一个已有项目/案件；
2. 展示业务文件夹可以被删除或调整；
3. 展示系统关键目录仍被保护；
4. 新建一个工作空间时展示“默认四类 / 空白结构”的选择差异。

### 2. 主台与悬浮窗快速切换体验优化

早期悬浮窗入口较深，用户从主台进入悬浮窗、再回到主台的路径不够顺手。本轮完成了悬浮窗切换体验的系统优化。

已经完成的工作包括：

- 增加全局快捷键 `Ctrl+Shift+Space`，支持主台与悬浮窗双向切换；
- 主窗顶部增加“切换到悬浮窗”按钮；
- 悬浮窗增加显眼的“回中台”入口；
- 增加系统托盘入口，支持打开主台、打开悬浮窗和退出；
- 将窗口切换从“关闭再重建”改为“隐藏与恢复”，减少等待和状态丢失；
- 增加淡入淡出过渡与可视化拖拽把手，让悬浮窗更像一个稳定的桌面工具。

这项优化解决的是高频使用路径。用户不需要记住复杂入口，也不需要担心切换后状态丢失。

**演示内容**

展示三种切换方式：

1. 使用 `Ctrl+Shift+Space` 在主台和悬浮窗之间切换；
2. 从主台顶部按钮进入悬浮窗；
3. 从悬浮窗点击“回中台”返回主界面。

### 3. 网页剪藏与 OCR 能力升级

资料采集是 IPM 的核心场景之一。旧的网页剪藏在复杂网页、动态渲染页面、代理或反爬场景下容易出现抓取不完整的问题。本轮对网页采集和 OCR 能力进行了升级。

已经完成的工作包括：

- 网页抓取升级为 Electron 隐藏窗口渲染方案，提升动态网页内容获取能力；
- 保留 HTTP 降级策略，避免渲染失败时完全不可用；
- 支持网页内容转换为 Markdown，提升后续阅读和 AI 处理质量；
- 支持全页截图和截图管理；
- KnowClaw 网页搜索接入博查 Web Search，并和渲染抓取能力桥接；
- 设置页支持 API Key 配置；
- 当搜索或抓取失败时，LLM 能进行自然降级说明；
- OCR 接入 PP-OCRv5，采用 `ppu-paddle-ocr` 与 `onnxruntime-node` 的纯 Node.js 方案；
- 支持中英双模型，为图片资料、截图证据、扫描材料提供文字提取基础。

这部分能力直接提升了“外部资料进入 IPM 后能不能被 AI 理解”的质量。

**演示内容**

1. 打开一个网页并执行网页剪藏，展示内容抓取结果；
2. 选择一张包含文字的图片，展示 OCR 识别效果；
3. 说明 OCR 结果后续可以被 KnowClaw 用于总结、归档或生成材料。

## 四、KnowClaw Agent 能力升级

### 1. 模型切换与推理能力升级

KnowClaw 已从单一模型调用升级为支持模型切换、推理等级调节和状态显示的 Agent 面板。

已经完成的工作包括：

- 支持模型列表获取和模型切换；
- 切换到 OpenAI Responses API，并保留回退能力；
- 支持 thinkingLevel 调节，包含 off / low / medium / high；
- 在 UI 中展示模型思考过程；
- 增加 TokenPill、ContextPill 等状态信息，让用户了解会话消耗和上下文情况；
- Header 做响应式适配，窗口变窄时控件会折叠到菜单中，避免挤压。

这项升级让产品可以根据不同场景选择模型：简单任务用更快模型，复杂法律分析用更强模型。

**演示内容**

在 KnowClaw 顶部展示模型切换，切换不同模型后说明：

- 当前模型会影响输出质量、速度和成本；
- thinking 等级会影响复杂任务的推理深度；
- 会话状态栏可帮助用户判断长对话是否接近上下文上限。

### 2. 工作空间机制与文件树可视化

工作空间是本轮 KnowClaw 升级中最关键的产品概念之一。它定义了 AI 当前可以理解和操作的项目边界。用户切换工作空间，就相当于把 AI 放到另一个项目或案件资料范围中。

已经完成的工作包括：

- 支持每个会话绑定具体工作空间；
- 支持工作空间切换；
- 支持打开当前工作空间所在目录；
- 支持项目上下文文件；
- 右侧增加工作空间文件树；
- 文件树支持折叠、展开、点击、双击打开；
- AI 生成或修改文件时，文件树可高亮新增/修改文件；
- 工具执行过程有 heartbeat 状态条，显示 thinking、writing、tool 等状态；
- 空闲状态有倒计时提示，减少用户误以为“卡住”。

这项能力让 KnowClaw 从“聊天窗口”变成“围绕某个项目/案件工作的 AI 操作台”。

**演示内容**

1. 展示当前工作空间；
2. 切换到准备好的诉讼案件工作空间；
3. 展示右侧文件树内容随工作空间变化；
4. 后续生成文件时观察文件树高亮。

### 3. 基础业务任务能力：找文件、读材料、生成法律意见书

KnowClaw 已具备在工作空间内检索目标文件、阅读内容、理解上下文并输出新文档的能力。该能力是法律、项目管理、知识整理等场景中的核心链路。

相关升级包括：

- Agent 可调用读文件、写文件、搜索文件、列目录等工具；
- 工具调用过程会在前端显示；
- 复杂任务可自动创建任务清单；
- 写文件与编辑文件时支持预览，用户可以看到 AI 正在写入什么内容；
- 生成的文件可直接落到指定工作空间目录；
- 历史会话恢复后仍能回放工具调用和文件预览。

**演示内容**

使用以下提示词，让 KnowClaw 完成“定位资料、理解案情、生成文书”的完整链路：

```text
请在工作文件夹下找到门店租赁纠纷的案情摘要md文件，以及类案参考_情势变更租赁纠纷裁判规律的md文件。
1. 先阅读这两个文件并理解
2. 生成一份法律意见书草稿，在工作文件夹的过程文档文件夹中输出一份md文件
```

演示时重点观察：

- KnowClaw 是否能在当前工作空间内找到两份目标 md 文件；
- 是否会先阅读并理解文件内容；
- 是否会自动创建任务节点；
- 是否会在“过程文档”目录中生成法律意见书草稿；
- 生成过程中右侧文件树是否出现新增文件高亮；
- 工具调用卡片是否展示写入文件的内容预览。

### 4. 网页搜索与案件关联分析

KnowClaw 已完成网页搜索和网页抓取稳定性升级，不再只是读取本地材料，也可以根据案件问题主动检索公开信息。

已经完成的工作包括：

- 接入博查 Web Search；
- 搜索结果可与渲染抓取能力结合；
- 支持选择公开网页并总结内容；
- 可以要求模型说明检索结果与当前案件事实的关联；
- 搜索失败时支持自然降级，不会让用户只看到技术错误。

**演示内容**

使用以下提示词演示网页搜索与案件关联：

```text
请在网络上检索「民法典 533 条 情势变更 商业租赁 2023 2024 裁判观点」，
选 1 条最相关的公开网页，并说明与本案的关联。
```

该演示体现 KnowClaw 的能力不止是“搜索网页”，而是能够把公开资料和当前工作空间里的案件材料结合起来，形成可解释的判断。

### 5. 图片上传与文件上传

KnowClaw 支持多模态图片输入和普通文件上传。图片输入用于 Vision 模型识别和理解图片内容；普通文件上传则会落盘到当前工作空间，再由模型通过文件工具读取。

已经完成的工作包括：

- 图片支持本地选择、粘贴和拖拽；
- 图片会自动压缩和缩放，避免过大导致传输或模型处理失败；
- 非 Vision 模型会自动隐藏图片入口或降级；
- 文件上传支持拖入工作空间；
- 文件树支持拖拽上传到目标目录；
- ChatInput 支持从文件树拖入文件引用；
- 系统文件拖入输入框后会复制到工作空间，并自动插入 `@relPath` 引用；
- 发给模型时，`@relPath` 会展开成明确的读取提示，让模型知道需要使用 read_file 读取对应文件。

**演示内容**

1. 上传一张图片，让 KnowClaw识别或总结图片内容；
2. 上传一个普通文件，展示文件被保存到当前工作空间；
3. 从文件树拖拽文件到输入框，展示 `@relPath` 引用；
4. 让 KnowClaw 根据上传文件继续分析或生成材料。

### 6. Plan 模式与 ask_user 交互

KnowClaw 已支持 Plan 模式。该模式下，AI 会先做只读分析、提出问题、保存计划，并在用户确认后再开始执行。这个机制尤其适合法律、合规、合同、证据整理等需要谨慎确认的场景。

已经完成的工作包括：

- Header 增加 PlanModeToggle；
- Plan 模式下通过 prompt 明确要求“先规划再执行”；
- 写入、编辑、bash、编辑型子任务会被拦截；
- 只读搜索、阅读、研究型子任务仍可使用；
- 新增 `ask_user` 工具，支持结构化提问；
- 新增 `AskUserCard`，用户可以在对话中选择或填写答案；
- 新增 `save_plan` 工具，可把计划保存到工作空间；
- 计划完成后出现“开始执行”按钮，用户确认后切回 Agent 模式执行。

这项能力让 KnowClaw 从“直接替用户做事”升级为“先对齐方案，再执行任务”。

**演示内容**

在一个需要用户确认的任务中打开 Plan 模式，观察模型是否主动提出问题。用户在 AskUserCard 中回答后，模型继续完善方案，并在确认后开始执行。

### 7. 子任务分发、任务追踪与过程可视化

本轮 KnowClaw 增加了复杂任务管理能力。对于多步骤任务，AI 可以创建任务清单；对于需要拆解的工作，可以委托子任务；对于写文件和编辑文件，用户可以看到更清晰的执行过程。

已经完成的工作包括：

- 子任务分发工具 `delegate_task`；
- 子任务执行隔离，避免递归调用和上下文污染；
- 子任务可区分 research / edit 类型；
- 子任务有轮次、工具调用次数、耗时等结果摘要；
- 任务追踪工具 `task_manager`；
- 对话中显示 TaskCard；
- TaskCard 支持完成状态、摘要状态和历史恢复；
- ToolCallCard 支持工具参数摘要、执行中状态、完成耗时；
- write / edit 文件变更支持内容预览和差异展示；
- ThinkingBlock 增加流式光标和动态视觉效果；
- 右侧对话导航条可帮助用户在长对话中定位历史节点。

这些能力让用户可以判断 AI 当前执行到了哪一步，减少“黑盒感”。

**演示内容**

在法律意见书生成任务中观察：

- 是否出现任务节点；
- 是否能看到工具调用；
- 是否能看到文件写入预览；
- 任务完成后 TaskCard 状态是否更新。

### 8. 工作空间文件整理能力

KnowClaw 已具备对当前工作空间内文件进行分类、创建子文件夹、移动文件的能力。这类能力面向真实业务中常见的“历史资料混乱、命名不统一、材料散落”的问题。

相关能力来自工作空间工具、文件树、写入/编辑预览、文件上传引用和任务追踪的组合。

**演示内容**

在准备好的诉讼案件工作空间中使用以下提示词：

```text
整理一下当前工作空间的文件，分门别类的去分类，创建子文件夹，然后整理
```

演示时观察：

- KnowClaw 是否先扫描当前文件；
- 是否能根据文件名和内容进行分类；
- 是否会创建子文件夹；
- 是否能把文件移动到对应类别中；
- 文件树是否同步刷新。

## 五、Skill 系统建设

### 1. Skill 管理能力

Skill 是 KnowClaw 从通用 Agent 走向专业工作流的重要基础。它可以理解为一组可复用的专业操作说明和辅助脚本，例如生成 PPT、处理 PDF、操作 Excel、生成网页报告等。

本轮完成了完整的 Skill 管理系统。

已经完成的工作包括：

- **SK0 Skill 服务层与 IPC 基础设施**：新增 Skill IPC，主进程可以扫描、读取、导入、删除和刷新 Skill。
- **SK1 Skill 管理 UI**：右侧面板展示已加载 Skill，支持查看详情、启用、禁用和删除。
- **SK2 外部 Skill 导入**：支持本地目录导入，支持冲突处理、覆盖、改名和批量导入进度。
- **SK3 热更新与悬浮窗集成**：新增/禁用 Skill 后不需要重启应用，下次会话自动生效；悬浮窗与主台共享 Skill 状态。
- **SK4 工作空间级 Skill**：支持 `<workspace>/.knowclaw/skills/`，不同项目或案件可以拥有自己的专属 Skill。
- **SK5 Skill Selector 输入器**：在输入框旁增加 Puzzle 弹窗，可搜索、多选并挂载 Skill，发送时直接注入对应 SKILL.md 内容，减少模型第一轮读取 Skill 的成本。

Skill 系统补齐后，KnowClaw 不再只是“一个模型 + 一组工具”，而是可以沉淀行业动作和团队流程的能力平台。

### 2. 内置与可导入 Skill

当前系统已经具备内置 Skill 和用户 Skill 的双层能力：

- 内置 `skill-builder`，可指导 AI 创建新 Skill；
- 内置 PDF、DOCX、XLSX、PPTX、web-artifacts-builder 等文档处理 Skill；
- 支持导入兼容 Agent Skills 标准的外部 Skill；
- 支持用户级 Skill 和工作空间级 Skill；
- 支持启用/禁用单个 Skill，避免无关 Skill 消耗上下文。

**演示内容**

演示 Skill 上传、挂载和使用。可以导入或选择 PPT 相关 Skill，然后使用以下提示词：

```text
根据这份文件，生成ppt
```

演示时可展示：

- Skill 管理面板中的 Skill 列表；
- 导入 Skill 的过程；
- 输入框旁 Skill Selector 选择 Skill；
- 模型根据文件和 Skill 生成 PPT。

## 六、悬浮窗 KnowClaw

### 1. 悬浮窗独立 Agent 通道

悬浮窗 KnowClaw 不是简单把主台聊天框缩小，而是建立了独立通道和固定工作空间，让用户可以在任意界面快速唤起 AI。

已经完成的工作包括：

- **FK0 双通道基础设施**：主台 KnowClaw 和悬浮窗 KnowClaw 分通道运行，互不干扰；
- 自动创建 `_floating/` 工作空间，用于悬浮窗临时资料和截图产物；
- `knowclawFloating` 独立命名空间，保证主台向后兼容；
- 悬浮窗 rail 增加 KnowClaw 模式入口；
- 支持缩略输入态、展开态和历史会话抽屉；
- 支持悬浮窗内模型和 thinking 设置。

这让悬浮窗从“快捷入口”升级为“轻量 AI 工作台”。

### 2. 外部回复气泡与展开对话

为了避免 AI 回复挤压悬浮窗，本轮做了外部气泡方案。

已经完成的工作包括：

- 独立 BrowserWindow 承载外部气泡；
- 自动计算气泡位置，适配屏幕边界；
- 气泡支持 show / hide / setContent / expandRequest；
- 玻璃态 BubbleView 展示 AI 回复；
- 用户需要长上下文时，可以一键展开为完整对话视图；
- Esc 支持分层关闭，顺序覆盖气泡、预览卡、OCR 卡、历史抽屉、设置面板、展开态和主模式。

该设计让悬浮窗保持轻量，但又不牺牲长对话能力。

### 3. 一键截图、OCR 与 AI 分析

悬浮窗 KnowClaw 的重点能力是一键截图与 AI 分析。用户在任何工作界面看到内容后，可以直接截图并让 AI 总结、识别或解释。

已经完成的工作包括：

- 新增截屏 IPC，支持全屏截图；
- 支持截图产物保存；
- 支持截图笔记保存；
- 支持 Vision 模型检测；
- 支持 Vision 不可用时降级为 OCR 文本总结；
- 截图预览卡支持手动发送；
- OCR 结果可保存、复制、追问；
- OCR 原文落盘到 `_floating/captures/`；
- 剪贴板图片优先，失败后回退到截屏；
- 对屏幕权限、AI 请求失败、Vision 降级等情况提供错误态提示。

**演示内容**

1. 切换到悬浮窗 KnowClaw；
2. 点击截图按钮；
3. 发送截图给 AI 分析；
4. 展示外部气泡回复；
5. 如有 OCR 文本，展示复制 OCR 原文或保存结果。

### 4. 悬浮窗与主台工作空间衔接

悬浮窗适合即时处理，主台适合长任务处理。本轮打通了二者之间的衔接路径。

已经完成的工作包括：

- 悬浮窗增加“回到空间”；
- 主台工作空间列表中加入 `_floating` 分组；
- 主台 streaming 时阻断不安全切换并提示用户；
- Tray 增加“发送给 AI 分析”，文件会上传到 `_floating` 并注入 `@relPath`；
- 悬浮窗产物后续可回到主台继续处理。

这使悬浮窗不只是临时工具，而是可以和完整工作流连接。

**演示内容**

在悬浮窗中完成一次截图分析后，回到主台查看 `_floating` 工作空间中的产物，说明临时分析结果可以被继续整理、引用或输出。

## 七、文件接入与资料管理能力

### 1. 外部文件夹附属导入

很多用户已经有自己的本地文件夹，不希望为了使用 IPM 再复制一份资料。本轮完成了外部文件夹“附属导入”能力。

已经完成的工作包括：

- 导入外部文件夹时不复制原始资料；
- 在 IPM 数据存储区创建“附属壳”；
- 附属壳保存系统目录、元数据和描述信息；
- 外部目录结构会被扫描并同步；
- 重新打开应用后可再次扫描，反映外部目录变化；
- 前端和后端限制保持一致，避免用户看到可操作但实际失败。

这项能力降低了历史资料迁移成本，让 IPM 更适合接入真实团队已有资料。

### 2. 对话中上传和引用文件

文件上传能力已经和工作空间文件树、ChatInput、`@relPath` 引用联动。

用户可以：

- 将本机文件拖入文件树目录；
- 将文件拖入对话输入框；
- 从文件树拖出文件引用到输入框；
- 让模型根据引用文件继续分析。

这部分能力为“上传文件后生成 PPT”“上传证据后分析”“上传合同后总结风险”等场景打下基础。

## 八、当前版本可展示的完整业务场景

结合以上能力，当前版本已经可以展示一个完整的诉讼案件工作流：

1. 用户进入诉讼案件工作空间；
2. KnowClaw 切换到合适模型；
3. AI 在工作空间中定位案情摘要和类案参考；
4. AI 阅读并理解材料；
5. AI 自主创建任务节点；
6. AI 生成法律意见书草稿并保存到“过程文档”；
7. AI 检索公开网页，补充法律依据与裁判观点；
8. 用户上传图片或文件作为补充材料；
9. 用户导入或选择 PPT Skill，让 AI 生成汇报材料；
10. 在需要确认的地方，AI 通过 ask_user 向用户提问；
11. AI 整理工作空间文件，创建子文件夹并分类归档；
12. 用户切换到悬浮窗，对外部屏幕内容一键截图并让 AI 分析；
13. 悬浮窗产物可回到主台继续加工。

这条链路体现了 KnowClaw 当前的产品定位：它不是单一问答工具，而是围绕工作空间协助用户完成资料处理、分析判断、文档生成和归档整理的桌面 Agent。
